# 从 AI 使用者到 AI 系统构建者：Dual-Agent-Harness 的诞生

## 起点：当 AI 不再只是一个聊天窗口

最开始接触人工智能时，我和大多数人一样，把 AI 当作一个更加聪明的搜索工具或者问答助手。

遇到问题：

- 不理解的数学概念；
- 写论文遇到困难；
- 编程出现 bug；
- 想设计一个游戏机制；

打开聊天窗口，输入问题，然后等待回答。

这种方式已经非常强大。

但是随着使用时间增加，我逐渐发现一个问题：

**AI 的能力越来越强，但是人与 AI 的协作方式似乎仍然停留在最初阶段。**

大部分时候，我们依然是在：

```
人提出问题
    ↓
AI 给出回答
    ↓
对话结束
```

这种模式下，AI 更像一个「高级工具」。

但是如果 AI 真正成为未来生产力的一部分，它应该不只是回答一次问题，而应该能够：

- 理解长期目标；
- 记住项目背景；
- 主动拆解任务；
- 执行具体工作；
- 根据结果调整方案。

也就是说：

> AI 不应该只是一个聊天对象，而应该成为一个长期合作的智能系统。

这成为我开始探索 Agent 架构的起点。

---

# 为什么需要多个 AI？

在实际使用过程中，我发现不同模型之间存在明显的特点差异。

有些模型更适合：

- 理解复杂问题；
- 进行逻辑分析；
- 制定计划；
- 发现错误。

而有些模型更适合：

- 修改大量代码；
- 操作文件；
- 快速执行任务；
- 进行工程实现。

如果强行让一个 AI 完成所有事情，实际上并不能发挥它最大的优势。

这让我想到软件工程中的团队协作：

一个大型项目不会让一个程序员完成所有事情。

通常会有：

- 架构设计者；
- 开发工程师；
- 测试人员；
- 产品负责人。

那么 AI 是否也可以采用类似结构？

于是产生了最初的想法：

```markdown
            人类

              |

              |

        AI Planner

      负责思考和规划

              |

              |

          Task Plan

              |

              |

       AI Executor

       负责执行任务

              |

              |

        Result Report

              |

              |

       AI Reviewer

       负责检查和改进
```

在这个体系中：

GPT 更像一个架构师。

DeepSeek 更像一个工程执行者。

它们不是互相替代，而是形成协作关系。

# 第一个真正的问题：如何让两个 AI 共存？

最初我认为这个问题很简单：

安装两个客户端即可。

但是实际操作后发现，现代软件远比想象复杂。

一个应用程序并不是只有一个 `.exe` 文件。

它还包含：

```diff
程序本体

+

配置文件

+

用户身份

+

缓存数据

+

数据库

+

插件

+

登录状态

+

系统注册信息
```

如果两个 AI 客户端直接共用这些内容，就会产生各种问题：

- 登录状态互相影响；
- 聊天记录混合；
- 项目列表冲突；
- 插件环境污染；
- 桌面图标无法区分。

这让我第一次真正意识到：

> 软件运行的本质，不只是代码，而是代码运行时所处的整个环境。

# Windows 软件隔离的探索

为了实现两个独立 AI 环境，我开始研究 Windows 应用运行机制。

最终发现，需要解决三个层面的问题。

---

## 第一层：配置隔离

首先需要让两个 AI 拥有不同的配置环境。

Codex 使用：

```
CODEX_HOME
```

作为主要配置目录。

因此：

官方 GPT：

```yaml
C:\Users\User\.codex
```

DeepSeek：

```yaml
C:\Users\User\.codex-deepseek
```

两个目录分别保存：

- 模型配置；
- 项目信息；
- 插件；
- 用户状态。

这样两个 Agent 才真正拥有自己的「大脑」。

---

## 第二层：数据隔离

仅仅分开配置还不够。

现代应用大量依赖缓存和数据库。

例如：

- web-data；
- session；
- cache；
- browser 数据。

因此需要进一步建立：

```
Official Profile

↓

OpenAI 数据环境


DeepSeek Profile

↓

DeepSeek 数据环境
```

避免两个实例互相读取历史状态。

---

## 第三层：系统身份隔离

最后一个问题是 Windows 层面。

虽然两个窗口看起来不同，但是系统可能认为：

「这是同一个应用。」

于是任务栏会自动合并。

为了解决这个问题，需要使用：

```
AppUserModelID
```

告诉 Windows：

这两个程序属于不同身份。

最终效果：

```
ChatGPT

🐟 DeepSeek Codex
```

成为两个独立的软件入口。

---

# 从解决问题到理解系统

这个项目最大的收获，并不是写出了多少代码。

而是在解决问题过程中，我开始重新理解软件。

以前：

> 软件就是一个程序。

现在：

> 软件是程序、环境、状态和系统之间的共同作用。

一个看似简单的问题：

「为什么两个 AI 不能同时存在？」

背后涉及：

- 操作系统；
- 用户权限；
- 进程管理；
- 文件系统；
- 网络代理；
- 应用身份；
- 配置管理。

这也是软件工程真正复杂的地方。

# Agent 系统的下一步

Dual-Agent-Harness 目前只是一个起点。

它解决的是：

> 如何让多个 AI 在同一个电脑环境中独立运行。

但是未来真正重要的问题是：

如何让 AI 之间形成稳定协作。

例如：

```
用户提出目标

↓

Planner Agent

分析任务

↓

Executor Agent

执行任务

↓

Reviewer Agent

检查结果

↓

Memory Agent

保存经验
```

最终形成一个属于个人的 AI 工作系统。

---

# 为什么想分享这个项目？

很多人认为 AI 的未来是：

「拥有更强大的模型。」

但我认为另一个方向同样重要：

> 普通人如何拥有属于自己的 AI 系统。

未来每个人可能都拥有自己的：

- AI 助手；
- AI 工程师；
- AI 研究伙伴；
- AI 管理系统。

但是要实现这一点，不只是需要更强的模型，也需要普通用户能够理解：

AI 如何运行。

AI 如何组织。

AI 如何成为一个真正属于自己的工具。

---

# 写在最后

这个项目最初只是一个非常实际的问题：

「如何让两个 AI 客户端互不干扰？」

但是在解决这个问题的过程中，我逐渐发现：

这其实是一个关于未来人机协作方式的小型探索。

从复制一个客户端，到理解 Windows 系统，再到设计 Agent 架构。

这个过程让我意识到：

未来的软件开发，也许不只是人与代码的关系。

而是：

```
人

↓

智能系统

↓

多个 AI Agent

↓

完成复杂目标
```

Dual-Agent-Harness 是我迈出的第一步。

它不是一个终点。

而是建立个人 AI 工作系统的开始。
